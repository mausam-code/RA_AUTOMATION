1. IS THE WEB AND MOBILE APP PROJECT IN THE SAME DIRECTORY?
--------------------------------------------------------------------------------
YES. Both the Desktop Web Operations Hub and the Mobile Staff App Companion 
are housed together in this SINGLE unified codebase (directory).

Benefits of this unified architecture:
- Shared Business Logic: Both Web and Mobile use the exact same state,
  types, OCR parsers, DFFEMS API Gateway, WhatsApp automation engine, and 
  accounting calculation modules.
- Instant View Switcher: On the top navigation bar, you can click "Web Hub" 
  for the full enterprise desktop operations screen or "Mobile App" for the 
  optimized mobile field operator view with bottom navigation.
- Responsive & Adaptive: If accessed on a smartphone or tablet screen, the
  interface automatically adapts to touch targets (>= 44px).
- Zero Duplicate Code: You don't have to maintain two separate codebases or 
  sync data across two different repositories.

3. STEP-BY-STEP INSTALLATION & DEVELOPMENT RUN
--------------------------------------------------------------------------------
Follow these exact steps from the project root directory:

STEP 1: Open Terminal / Command Prompt
  Navigate to the project root directory where package.json is located:
  cd /path/to/project

STEP 2: Install Project Dependencies
  Run the npm install command to install all required packages:
  npm install

  Installed key dependencies include:
  - react & react-dom (React 19 SPA framework)
  - vite & @vitejs/plugin-react (ultra-fast build and dev server)
  - tailwindcss & @tailwindcss/vite (responsive styling)
  - lucide-react (icons for navigation, WhatsApp, OCR, auditing)
  - xlsx (SheetJS engine for generating real .xlsx spreadsheets)
  - @google/genai (Gemini Vision AI for biometric OCR parsing)

STEP 3: Start the Development Server
  Run the local development server:
  npm run dev

  The console will output:
  VITE v8.x.x  ready in ~200 ms
  ➜  Local:   http://localhost:3000/
  ➜  Network: http://0.0.0.0:3000/

STEP 4: Open in Your Browser
  Open your web browser and navigate to:
  http://localhost:3000/

4. STEP-BY-STEP PRODUCTION BUILD & DEPLOYMENT
--------------------------------------------------------------------------------
To compile an optimized, minified production build:

STEP 1: Run the Production Build Command
  npm run build

  This will run Vite's production bundler and create a `/dist` directory 
  containing minified JavaScript, CSS, HTML, and assets ready for static 
  hosting (e.g., Cloud Run, Vercel, Netlify, Nginx, AWS S3 / CloudFront).

STEP 2: Preview the Production Build Locally
  npm run preview

  This runs a local production HTTP server to verify the production bundle 
  before pushing to live deployment.

STEP 3: Type Checking & Linting
  To verify TypeScript syntax and types without emitting files:
  npm run lint

5. ENVIRONMENT VARIABLES & API KEY CONFIGURATION
--------------------------------------------------------------------------------
The project includes a `/.env.example` file.

To configure custom environment variables:
1. Create a local `.env` file in the root directory:
   cp .env.example .env

2. Available environment variables:
   - GEMINI_API_KEY: Optional. If provided, the OCR engine uses Gemini 3.8 Flash 
     Vision to extract passport and ID details. If not provided, the system 
     uses the built-in ICAO 9303 Doc 9303 MRZ scanner and smart pattern matcher.
   - VITE_DFFEMS_BASE_URL: Base URL for the government DFFEMS gateway. Defaults 
     to https://api.dffems.gov.np/v2/agency-gateway (mock sandbox enabled).

--------------------------------------------------------------------------------

   - Test in-chat action buttons ("Upload Clear Scan", "Enter Flight Details",

9. DFFEMS LIVE API GATEWAY REPLACEMENT GUIDE
--------------------------------------------------------------------------------
All API calls are centralized in `/src/services/dffemsApiService.ts`.

When the government DFFEMS team provides live endpoints:
1. Open the "DFFEMS API" modal in the top header.
2. Update the "Base URL" to the live production endpoint.
3. Switch Environment from `MOCK_SANDBOX` to `PRODUCTION_GATEWAY`.
4. In `/src/services/dffemsApiService.ts`, replace the `makeGenericResponse()` 
   calls with real `fetch()` or `axios()` requests using your live API key.

11. POSTGRESQL DATABASE SETUP & CONNECTION GUIDE
================================================================================
The project includes a ready-to-run PostgreSQL production schema in:
`/database/schema.sql`

A. RUN POSTGRESQL LOCALLY VIA DOCKER (RECOMMENDED):
   Run the included docker-compose.yml:
   docker compose up -d postgres

   This automatically boots PostgreSQL 16 on port 5432 and imports schema.sql.
   - Database Name: dffems_agency
   - Username: agency_admin
   - Password: SecretPostgresPassword2026!
   - Port: 5432

B. IMPORT TO AN EXISTING POSTGRESQL SERVER:
   psql -U your_postgres_user -d dffems_agency -f database/schema.sql

C. CLOUD POSTGRESQL (SUPABASE / NEON / GCP CLOUD SQL):
   1. Create a new PostgreSQL project on Supabase (https://supabase.com) or Neon.
   2. Open the SQL Editor in your cloud dashboard.
   3. Copy and run the contents of `/database/schema.sql`.
   4. Set your DATABASE_URL in your server .env file:
      DATABASE_URL="postgres://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres"

================================================================================
To host this system on a physical desktop PC or on-premise server in your office:

STEP 1: ASSIGN A STATIC LOCAL IP

  http://dffems.agency.local

13. SYNCING MOBILE APP & ACCESSING FROM ANYWHERE IN THE WORLD (INTERNET)
================================================================================
How do mobile field staff scan passports or view candidate statuses from remote
districts or airports without exposing the internal server to security risks?

METHOD A: CLOUDFLARE ZERO TRUST TUNNEL (EASIEST, 100% FREE & ZERO PORT FORWARDING)
1. Install cloudflared on your internal server:
   curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
   sudo dpkg -i cloudflared.deb

2. Authenticate and create a secure tunnel:
   cloudflared tunnel login
   cloudflared tunnel create dffems-tunnel

3. Route your custom domain (e.g. app.youragency.com) through the tunnel:
   cloudflared tunnel route dns dffems-tunnel app.youragency.com

4. Run the tunnel:
   cloudflared tunnel run --url http://localhost:80 dffems-tunnel

   RESULT:
   - Your internal server is now securely accessible worldwide at:
     https://app.youragency.com
   - No router ports to forward.
   - Built-in DDoS protection and free automatic SSL certificate.

14. GOOGLE PLAY STORE DEPLOYMENT FOR ANDROID (CAPACITOR)
================================================================================
The mobile app companion (`MobileCompanionView.tsx`) is already part of this unified
codebase. Follow these steps to package and release it to the Google Play Store:

STEP 1: INSTALL CAPACITOR DEPENDENCIES
  npm install @capacitor/core @capacitor/cli @capacitor/android

STEP 2: INITIALIZE & ADD ANDROID PLATFORM
  npx cap add android

STEP 3: COMPILE PRODUCTION WEB BUILD & SYNC
  npm run build
  npx cap sync android

STEP 4: GENERATE RELEASE SIGNING KEYSTORE
  keytool -genkey -v -keystore dffems-release.keystore -alias dffems_key -keyalg RSA -keysize 2048 -validity 10000

STEP 5: BUILD SIGNED ANDROID APP BUNDLE (.AAB)
  cd android
  ./gradlew bundleRelease

  Output bundle is generated at:
  android/app/build/outputs/bundle/release/app-release.aab

STEP 6: GOOGLE PLAY CONSOLE SUBMISSION
1. Log in to https://play.google.com/console
2. Create App -> Name: "DFFEMS Field Staff" -> Category: Business
3. Upload `app-release.aab` to Internal Testing or Production Track.
4. Complete the App Content questionnaire:
   - Camera permission: Required for Passport OCR scanning.
   - Internet permission: Required for syncing records to the office server.
5. Submit for Google review (typically takes 24-48 hours).
